# Service Worker Documentation (sw.js)

## Overview

The service worker (`sw.js`) acts as the central communication hub and orchestration layer for the Om_E_Web Chrome Extension. It bridges the WebSocket server, content scripts, and Chrome APIs to enable external control of web pages.

**Core Responsibilities:**
- Maintain WebSocket connection to server (port 17892)
- Route commands between server and content scripts
- Manage tab lifecycle and state tracking
- Coordinate DOM scanning operations
- Handle capability execution (smart routing)
- Manage extension keep-alive mechanisms
- Track site configurations for per-domain behavior

---

## Architecture Overview

### Communication Flow

```
┌─────────────────┐
│  WebSocket      │
│  Server         │
│  (port 17892)   │
└────────┬────────┘
         │
         ▼
┌─────────────────┐      ┌──────────────┐      ┌─────────────┐
│  Service Worker │─────▶│   Content    │─────▶│     DOM     │
│     (sw.js)     │◀─────│   Script     │◀─────│  (Web Page) │
└─────────────────┘      └──────────────┘      └─────────────┘
         │
         ▼
┌─────────────────┐
│  Chrome APIs    │
│  (tabs, etc)    │
└─────────────────┘
```

### Message Flow Round-Trip

1. **Server → SW**: WebSocket receives command
2. **SW → Content**: chrome.tabs.sendMessage forwards to content script
3. **Content → DOM**: Content script executes on page
4. **Content → SW**: sendResponse returns result
5. **SW → Server**: WebSocket sends response back
6. **Server → Client**: Routes to original test client

## Function Reference

### WebSocket Management

#### `connectWebSocket()`
**Purpose**: Establish and maintain WebSocket connection to server

**Flow**:
1. Check if connection already exists/connecting
2. Create new WebSocket to `ws://127.0.0.1:17892`
3. Set up event handlers (onopen, onmessage, onclose, onerror)
4. On open: send bridge_status, tabs info, active tab info, flush pending messages
5. On close: attempt reconnect after 1s delay

**Called by**: Startup, reconnection logic, extension installation
**Calls**: sendToServer(), sendTabsInfo(), sendActiveTabInfo(), flushPendingMessages(), sendHeartbeat()

---

#### `sendToServer(data)`
**Purpose**: Send JSON message to WebSocket server

**Parameters**:
- `data` (Object): Message payload

**Behavior**:
- If WebSocket open: send immediately
- If WebSocket not ready: queue in pendingMessages array

**Called by**: All functions sending data to server
**Calls**: ws.send()

---

#### `flushPendingMessages()`
**Purpose**: Send queued messages when WebSocket becomes ready

**Flow**:
1. Check if pendingMessages has items and WebSocket is open
2. Copy messages to temporary array and clear queue
3. Send each message via WebSocket
4. Log errors if sending fails

**Called by**: connectWebSocket() after connection established
**Calls**: ws.send()

### Keep-Alive System

#### `ensureKeepAlivePort()`
**Purpose**: Prevent Chrome from suspending the service worker

**Strategy**:
1. Check if keepAlivePorts already exist (return if yes)
2. Try creating offscreen document first
3. Fallback: inject keep-alive helper into accessible HTTP(S) tab
4. Helper creates persistent port connection named "ome_keep_alive"

**Called by**: Tab events, periodic check (30s interval), alarm handler
**Calls**: ensureOffscreenDocument(), chrome.scripting.executeScript()

---

#### `ensureOffscreenDocument()`
**Purpose**: Create offscreen document to host keep-alive port

**Flow**:
1. Check if chrome.offscreen API available
2. Check if document already exists
3. Create offscreen.html with TESTING reason
4. Used when no regular tabs available

**Called by**: ensureKeepAlivePort()
**Calls**: chrome.offscreen.createDocument()

---

#### `scheduleHeartbeatAlarm()`
**Purpose**: Create periodic alarm to wake service worker

**Parameters**: None
**Creates**: Alarm named "ome_ws_heartbeat" every 1 minute

**Called by**: Startup, installation
**Calls**: chrome.alarms.create()

---

#### `sendHeartbeat(reason)`
**Purpose**: Send ping to server to verify connection alive

**Parameters**:
- `reason` (string): Why heartbeat sent ("manual", "alarm", "onopen")

**Sends**:
```javascript
{
  type: "ping",
  source: "extension",
  reason: string,
  keepAlivePorts: number,
  timestamp: number
}
```

**Called by**: connectWebSocket(), alarm handler
**Calls**: sendToServer()

### Scan Orchestration

#### `requestScan(tabId, url, trigger)`
**Purpose**: Single entry point for ALL scan triggers - prevents duplicate scans

**Parameters**:
- `tabId` (number): Tab to scan
- `url` (string): Current URL
- `trigger` (string): Reason for scan ("url_change", "page_refresh", "tab_switch", "post_action", "post_scroll", "spa_navigation", etc.)

**Flow**:
1. Log scan request with counter and timestamp
2. Skip chrome:// URLs
3. Check if scan already in progress (dedupe)
4. Check if same URL already scanned (skip unless forced trigger)
5. Force scan triggers: post_action, significant_dom_change, page_refresh, tab_switch, post_scroll, inputPattern_submit
6. Mark scan in progress in tabState
7. Inject content script
8. Send 'start_scan' message to content script

**State Management**:
```javascript
tabState.set(tabId, {
  scanInProgress: true,
  lastUrl: url
});
```

**Called by**: Navigation listeners, tab activation, DOM command completion, action completion
**Calls**: chrome.scripting.executeScript(), chrome.tabs.sendMessage()

---

#### `handleScanComplete(message, sender)`
**Purpose**: Process scan completion from content script

**Flow**:
1. Get tabId from sender
2. Mark scan as complete in tabState (scanInProgress = false)
3. Forward intelligenceData to server via WebSocket

**Message sent to server**:
```javascript
{
  type: 'intelligence_update',
  data: message.intelligenceData
}
```

**Called by**: onMessage listener when type='scan_complete'
**Calls**: ws.send()

---

#### `triggerIntelligenceScan(tabId, url, reason)` **[DEPRECATED]**
**Purpose**: Legacy function - redirects to requestScan()

**Status**: Kept for compatibility, logs deprecation warning

### Tab Management

#### `sendTabsInfo(forceRefresh)`
**Purpose**: Query all tabs and send information to server

**Parameters**:
- `forceRefresh` (boolean): Whether to force refresh internal state

**Flow**:
1. Query all tabs via chrome.tabs.query({})
2. Map to tabsInfo array with id, url, title, active, status, pendingUrl
3. Update internal state via updateInternalTabState()
4. Send to server with type="tabs_info"
5. Also send active tab info

**Called by**: WebSocket connection, tab events, command handlers
**Calls**: chrome.tabs.query(), updateInternalTabState(), sendToServer(), sendActiveTabInfo()

---

#### `sendActiveTabInfo()`
**Purpose**: Send only the currently active tab information

**Flow**:
1. Query active tab in current window
2. Build activeTabInfo object
3. Send to server with type="active_tab_info"

**Message sent**:
```javascript
{
  type: "active_tab_info",
  activeTab: {
    id: number,
    url: string,
    title: string,
    status: string,
    pendingUrl: string
  },
  timestamp: number
}
```

**Called by**: WebSocket connection, tab activation, tab updates
**Calls**: chrome.tabs.query(), sendToServer()

---

#### `updateInternalTabState(tabsInfo, forceRefresh)`
**Purpose**: Maintain enhanced internal state for all tabs

**Parameters**:
- `tabsInfo` (Array): Array of tab information objects
- `forceRefresh` (boolean): Clear all state before updating

**Flow**:
1. If forceRefresh: clear internalTabState and tabCache
2. For each tab in tabsInfo:
   - Compare with old state
   - If changed (url, title, active, status):
     - Clear cache for tab
     - Update internal state with enhanced tracking
     - Initialize domChanges, siteConfig, networkActivity tracking
   - If new active tab: ensure content script fresh
   - If URL changed: force content script refresh
3. Remove tabs that no longer exist

**Called by**: sendTabsInfo()
**Calls**: clearTabCache(), ensureContentScriptFresh()

---

#### `clearTabCache(tabId)`
**Purpose**: Clear cached data for specific tab

**Parameters**:
- `tabId` (number): Tab to clear

**Flow**:
1. Remove entry from tabCache Map
2. Mark tab as needsFreshScan in internalTabState
3. Set lastCacheClear timestamp

**Called by**: Navigation, tab updates, force refresh
**Calls**: None

---

#### `ensureContentScriptFresh(tabId)`
**Purpose**: Force re-injection of content script into tab

**Parameters**:
- `tabId` (number): Tab to refresh

**Flow**:
1. Check if actionInProgress (skip if true to prevent interrupting actions)
2. Inject content.js via chrome.scripting.executeScript
3. Proactively send site config after injection (calls proactivelySendSiteConfig - **NOTE: Function called but not defined**)
4. Mark tab as having fresh content script
5. On error: mark refresh as failed

**Called by**: Tab state updates, active tab changes, DOM command handlers
**Calls**: chrome.scripting.executeScript(), proactivelySendSiteConfig() (undefined)

---

#### `findActiveTab()`
**Purpose**: Find currently active accessible tab with multiple fallback strategies

**Returns**: Promise<Tab> or null

**Strategy**:
1. **Strategy 1**: Find active tab in current window
   - Filter for accessible (not chrome://)
   - Get refreshed tab info
2. **Strategy 2**: Find active tab in last focused window
3. **Strategy 3**: Find any accessible tab in current window
   - Sort by priority (non-chrome first, then active)
4. **Last Resort**: Find any visible accessible tab across all windows
   - Sort by active status

**Called by**: All command handlers needing active tab
**Calls**: chrome.tabs.query(), chrome.tabs.get(), chrome.windows.getCurrent(), isTabAccessible()

---

#### `isTabAccessible(tab)`
**Purpose**: Check if tab is accessible for content scripts

**Parameters**:
- `tab` (Object): Tab object

**Returns**: boolean

**Checks**:
- Has URL
- Not chrome://, chrome-extension://, about:, edge://, moz-extension://
- Not about:blank

**Called by**: findActiveTab()

**Purpose**: Central dispatcher for WebSocket messages from server

**Calls**: Various command handlers

### Command Handlers - DOM Operations

#### `handleDOMCommand(message)`
**Purpose**: Forward DOM commands to content script in active tab

**Handles commands**:
- waitFor, getText, click, getPageMarkdown, extractPageText
- scroll (page-by-page viewport scrolling)
- getCurrentTabInfo, getNavigationContext, searchActions
- discoverLoginControls, generateSiteMap, scanAndRegisterElements
- navigateBack, navigateForward, jumpToHistoryEntry
- getHistoryState, searchHistory, clearHistory

**Flow**:
1. Find active tab
2. Check if content script needs refresh (needsFreshScan or !contentScriptFresh)
3. Inject content script if needed
4. Proactively send site config after injection (calls undefined function)
5. Wait 100ms for content script initialization
6. Send message to content script via chrome.tabs.sendMessage
7. Handle response:
   - If error: send error response
   - If success: send success response
   - If scroll command: trigger post_scroll scan after 300ms

**Called by**: handleServerMessage()
**Calls**: findActiveTab(), ensureContentScriptFresh(), chrome.scripting.executeScript(), proactivelySendSiteConfig() (undefined), chrome.tabs.sendMessage(), sendSuccessResponse(), sendErrorResponse(), requestScan()

### Action Execution

#### `handleExecuteLLMAction(message, sendResponse)`
**Purpose**: Execute LLM-generated actions on page elements

**Message data**:
```javascript
{
  type: "execute_llm_action",
  data: {
    actionId: string,
    actionType: string,
    params: object
  }
}
```

**Flow**:
1. Set actionInProgress = true (prevents content script refresh during action)
2. Find active tab
3. Send execute_action message to content script

   - Clear actionInProgress flag
   - Send error response

**State coordination**:

- Clears on error/exception
- Note: **actionInProgress variable is used but not declared** (potential bug)

**Called by**: handleServerMessage(), onMessage listener
**Calls**: findActiveTab(), chrome.tabs.sendMessage(), requestScan()

### Tear Away System

#### `handleForceContentScriptReinjection(message, sendResponse)`
**Purpose**: Force re-inject content script (for CSP bypass scenarios)

**Message data**:
```javascript
{
  data: {
    tabId?: number,

  }
```

**Flow**:

3. Clear tab cache
4. Mark tab as needsFreshScan
5. Send success response

**Called by**: onMessage listener
**Calls**: getCurrentActiveTabId() (undefined), ensureContentScriptFresh(), clearTabCache()

---

#### `handleForceExtensionReload(message, sendResponse)`
**Purpose**: Force extension reload (requires manual user action)

**Message data**:
```javascript
{
  data: {
    reason: string,
    timestamp: number,
    forceReload?: boolean
  }

```

1. Clear all internal state

3. If forceReload:
   - Query all active tabs

**Called by**: onMessage listener

```javascript
{
  data: {
    scanType: string,
    elementCounts: object,
    frameContext: object,
    scanDuration: number,
    tearAwaySuccess: boolean
  }
}
```

**Flow**:
1. Log scan result summary
2. Send to server via WebSocket with type="immediate_scan_results_after_tear_away"

**Called by**: onMessage listener from content script
**Calls**: ws.send() or queues in pendingMessages

### 6. Keep-Alive Mechanism

```
                 │
                 ▼

│ Strategy 1: Persistent Port Connection                         │

                 │
```

## Known Issues and Notes

### 1. Undefined Variables/Functions

**actionInProgress**
- Used in: ensureContentScriptFresh(), handleDOMChanged(), handleNetworkActivity(), handleExecuteLLMAction()
- Problem: Variable is referenced but never declared
- Impact: Will cause ReferenceError if used before assignment in handleExecuteLLMAction()
- Fix needed: Declare at top of file with other state variables

**proactivelySendSiteConfig(tabId, url)**
- Called in: ensureContentScriptFresh(), handleDOMCommand()
- Problem: Function is called but not defined anywhere in file
- Impact: Will cause ReferenceError when called
- Fix needed: Define function or remove calls

**getCurrentActiveTabId()**
- Called in: handleForceContentScriptReinjection()
- Problem: Function is called but not defined anywhere in file
- Impact: Will cause ReferenceError when called
- Alternative: Use findActiveTab() instead

---

### 2. Disabled Features

**Page Version System** (lines 38-221)
- Entire system commented out
- Previously tracked page versions per tab+domain
- Replaced with simple sequential IDs in text.md
- Can be safely deleted after testing confirms no issues

**DOM Mutation Rescans** (line 1659-1677)
- Full rescans on DOM mutations disabled
- Reason: Caused counter accumulation, ID inconsistency, overlapping scans
- Now: content.js handles mutations incrementally via registerInteractiveSubtree

**Network Idle Rescans** (line 1741-1754)
- Automatic rescans during action execution disabled
- Reason: Prevents invalidating action IDs before actions complete
- Now: Rescans triggered post-action instead

---

### 3. Deprecated Code

**triggerIntelligenceScan()** (line 636-639)
- Marked as deprecated
- Redirects to requestScan()
- Kept for compatibility
- Should be removed after updating all callers

**tabScanState Map** (line 230)
- Marked as deprecated
- Still used in some listeners for cleanup
- Will be removed in future

---

### 4. Design Notes

**Scan Deduplication**
- Only one scan can run per tab at a time
- Same URL scans are skipped unless forced trigger
- Forced triggers: post_action, significant_dom_change, page_refresh, tab_switch, post_scroll, inputPattern_submit

**Action Coordination**
- actionInProgress flag prevents content script refresh during action execution
- Post-action scan triggered after 1s delay
- This ensures action IDs remain valid during execution

**Tab Accessibility**
- chrome://, about:, chrome-extension:// URLs are not accessible for content scripts
- findActiveTab() implements multiple fallback strategies
- Prioritizes non-chrome tabs over chrome:// tabs

**Keep-Alive Strategy**
- Multiple redundant mechanisms to prevent suspension
- Port connections from content scripts most reliable
- Offscreen document fallback for when no tabs available
- Periodic checks and alarms as additional safety nets

### Common Issues

**WebSocket not connecting**
- Check ws_server.py is running on port 17892
- Check console for connection errors
- Verify no firewall blocking localhost:17892

**Content script not responding**
- Check tab is accessible (not chrome://)
- Verify content script injected (check tab's console)
- Try force refresh via popup

**Scans not triggering**
- Check scan deduplication logic
- Verify trigger type is in forced list if needed
- Check scanInProgress flag not stuck

**Actions failing**
- Verify actionId exists in content script registry
- Check active tab is correct
- Monitor actionInProgress flag state

## Summary

The service worker is the central nervous system of Om_E_Web, orchestrating:
- **Bidirectional communication** between server and content scripts
- **Tab lifecycle management** with intelligent state tracking
- **Scan coordination** with deduplication and trigger routing
- **Keep-alive mechanisms** to prevent Chrome suspension
- **Site configuration distribution** for per-domain behavior
- **Smart capability routing** between browser-level and page-level operations

It implements a robust, event-driven architecture with multiple fallback strategies for reliability. Key to its operation is the clear separation between:
- **Browser-level operations** (handled directly via Chrome APIs)
- **Page-level operations** (forwarded to content scripts)
- **State synchronization** (maintaining consistency across components)
