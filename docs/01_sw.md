# Service Worker Documentation (sw.js)

## Overview

The service worker (`sw.js`) acts as the central communication hub and orchestration layer for the Om_E_Web Chrome Extension. It bridges the WebSocket server, content scripts, and Chrome APIs to enable external control of web pages.

**Core Responsibilities:**
- Maintain persistent WebSocket connection to server (port 17892)
- Route commands bidirectionally between server and content scripts
- Manage tab lifecycle with enhanced state tracking
- Coordinate DOM scanning operations with deduplication
- Handle capability execution with smart routing (browser vs page-level)
- Manage extension keep-alive mechanisms to prevent suspension
- Track and distribute site configurations for per-domain behavior
- Persist and synchronize orb UI state across navigations
- Bridge chat system between HUD interface and server
- Merge iframe intelligence with main frame elements for cross-origin support

## Architecture Overview

### Communication Flow

```
┌─────────────────┐
│  WebSocket      │
│  Server         │
│  (port 17892)   │
└────────┬────────┘
         │
         ▼
┌─────────────────┐      ┌──────────────┐      ┌─────────────┐
│  Service Worker │─────▶│   Content    │─────▶│     DOM     │
│     (sw.js)     │◀─────│   Script     │◀─────│  (Web Page) │
└─────────────────┘      └──────────────┘      └─────────────┘
         │
         ▼
┌─────────────────┐
│  Chrome APIs    │
│  (tabs, etc)    │
└─────────────────┘
```

### Message Flow Round-Trip

1. **Server → SW**: WebSocket receives command
2. **SW → Content**: chrome.tabs.sendMessage forwards to content script
3. **Content → DOM**: Content script executes on page
4. **Content → SW**: sendResponse returns result
5. **SW → Server**: WebSocket sends response back
6. **Server → Client**: Routes to original test client

## Function Reference

### WebSocket Management

#### `connectWebSocket()`
**Purpose**: Establish and maintain WebSocket connection to server on ws://127.0.0.1:17892

**Flow**:
1. Check if connection already exists or connecting, return if yes
2. Create new WebSocket instance
3. Set up event handlers:
   - `onopen`: Send bridge_status, tabs info, active tab info, flush pending messages, send heartbeat
   - `onmessage`: Delegate to handleServerMessage()
   - `onclose`: Attempt reconnection after 100ms delay
   - `onerror`: Log error
4. On error: retry connection after 100ms

**Called by**: Startup, onInstalled, onStartup, reconnection logic, handleSetWsUrl
**Calls**: sendToServer(), sendTabsInfo(), sendActiveTabInfo(), flushPendingMessages(), sendHeartbeat()

---

#### `sendToServer(data)`
**Purpose**: Send JSON message to WebSocket server, queue if not ready

**Parameters**:
- `data` (Object): Message payload to serialize

**Behavior**:
- If WebSocket open: send immediately via ws.send()
- If WebSocket not ready: queue in pendingMessages array
- Logs success or warning

**Called by**: All functions sending data to server
**Calls**: ws.send()

---

#### `flushPendingMessages()`
**Purpose**: Send queued messages when WebSocket becomes ready

**Flow**:
1. Check if pendingMessages has items and WebSocket is open
2. Copy messages to temporary array and clear queue
3. Send each message via ws.send()
4. Log errors if sending fails

**Called by**: connectWebSocket() after onopen event
**Calls**: ws.send()

### Keep-Alive System

#### `ensureKeepAlivePort()`
**Purpose**: Prevent Chrome from suspending the service worker using multiple strategies

**Strategy**:
1. Check if keepAlivePorts already exist (return if size > 0)
2. Try creating offscreen document first (works even with no tabs)
3. Fallback: inject keep-alive helper into accessible HTTP(S) tab
4. Helper creates persistent port connection named "ome_keep_alive"

**Called by**: Tab events, periodic check (30s interval), alarm handler, tab lifecycle events
**Calls**: ensureOffscreenDocument(), chrome.scripting.executeScript()

---

#### `ensureOffscreenDocument()`
**Purpose**: Create offscreen document to host keep-alive port when no regular tabs available

**Flow**:
1. Check if chrome.offscreen API available
2. Check if document already exists via hasDocument()
3. Create offscreen.html with TESTING reason
4. Log success or warning

**Called by**: ensureKeepAlivePort()
**Calls**: chrome.offscreen.createDocument()

---

#### `scheduleHeartbeatAlarm()`
**Purpose**: Create periodic alarm to wake service worker every 1 minute

**Called by**: Startup, installation, global initialization
**Calls**: chrome.alarms.create()

---

#### `sendHeartbeat(reason)`
**Purpose**: Send ping to server to verify connection alive

**Parameters**:
- `reason` (string): Why heartbeat sent ("manual", "alarm", "onopen")

**Sends**:
```javascript

  reason: string,

  timestamp: number
}
```

**Called by**: connectWebSocket(), alarm handler
**Calls**: sendToServer(), connectWebSocket() if not connected

### Scan Orchestration

#### `requestScan(tabId, url, trigger)`
**Purpose**: Single entry point for ALL scan triggers with deduplication

**Parameters**:
- `tabId` (number): Tab to scan
- `url` (string): Current URL
- `trigger` (string): Reason for scan

**Trigger types**:
- url_change, page_refresh, tab_switch, spa_navigation
- post_action, post_scroll, inputPattern_submit
- significant_dom_change, network_idle, dom_mutation

**Flow**:
1. Log scan request with counter and timestamp
2. Skip chrome:// URLs
3. Check if scan already in progress (dedupe)
4. Check if same URL already scanned
5. Allow forced rescans for specific triggers:
   - post_action, significant_dom_change, page_refresh
   - tab_switch, post_scroll, inputPattern_submit
6. Mark scanInProgress = true in tabState
7. Set lastUrl to current URL
8. Inject content script via chrome.scripting.executeScript
9. Send start_scan message to content script with trigger and URL

**State Management**:
```javascript
tabState.set(tabId, {
  scanInProgress: true,
  lastUrl: url
});
```

**Called by**: Navigation listeners, tab activation, DOM command completion, action completion, content script request
**Calls**: chrome.scripting.executeScript(), chrome.tabs.sendMessage()

---

#### `handleScanComplete(message, sender)`
**Purpose**: Process scan completion from content script, send to server

**Flow**:
1. Get tabId from sender.tab.id
2. Mark scanInProgress = false in tabState
3. Extract intelligenceData and expectedIframeCount
4. Clear old iframe cache for this tab (new scan = fresh start)
5. Send main frame intelligence immediately (progressive output)
6. If iframes expected:
   - Store in pendingScanCache for merging
   - Set timeout to send partial results after 5s if iframes don't report

**Called by**: onMessage listener when type='scan_complete'
**Calls**: sendMainFrameIntelligence(), setTimeout() for iframe timeout

---

#### `sendMainFrameIntelligence(tabId, intelligenceData, pendingIframeCount)`
**Purpose**: Send main frame intelligence immediately without waiting for iframes

**Parameters**:
- `tabId` (number): Tab ID
- `intelligenceData` (Object): Main frame scan data
- `pendingIframeCount` (number): How many iframes we're waiting for

**Flow**:
1. Check WebSocket is ready
2. Extract main frame actionables from semanticPageData
3. Set actionableElements to main frame only
4. Add metadata: pendingIframeCount, iframeStatus ('loading' or 'none')
5. Send to server with type='intelligence_update'

**Progressive Strategy**: LLM gets main frame data immediately, iframe elements sent separately

**Called by**: handleScanComplete()
**Calls**: ws.send()

---

#### `sendIframeUpdate(tabId, intelligenceData)`
**Purpose**: Send iframe elements update after all iframes report or timeout

**Parameters**:
- `tabId` (number): Tab ID
- `intelligenceData` (Object): Original intelligence data

**Flow**:
1. Check WebSocket is ready
2. Get main frame actionables to calculate starting ID
3. Merge iframe intelligence
4. Extract just the iframe elements (slice from main frame length)
5. Update iframe DOM with final IDs via broadcast to all frames
6. Send to server with type='iframe_elements_update'
7. Clear pendingScanCache

**Called by**: handleIframeIntelligence(), handleDynamicIframeDetected() timeout
**Calls**: mergeIframeIntelligence(), chrome.scripting.executeScript(), ws.send()

---

#### `sendFinalIntelligence(tabId, intelligenceData)`
**Purpose**: Send final merged intelligence (main + iframes) - **NOTE: Appears unused, progressive output used instead**

**Flow**:
1. Check WebSocket ready
2. Get main frame actionables
3. Merge iframe intelligence and get ID mappings
4. Update intelligenceData.actionableElements with merged list
5. Broadcast ID updates to all iframe frames
6. Send to server with type='intelligence_update'
7. Clear pendingScanCache

**Called by**: Not currently called (replaced by progressive output)
**Calls**: mergeIframeIntelligence(), chrome.scripting.executeScript(), ws.send()

---

#### `triggerIntelligenceScan(tabId, url, reason)` **[DEPRECATED]**
**Purpose**: Legacy function - redirects to requestScan()

**Status**: Kept for compatibility, logs deprecation warning

**Called by**: Legacy code (being phased out)
**Calls**: requestScan()

### Iframe Intelligence

#### `handleIframeIntelligence(message, sender, sendResponse)`
**Purpose**: Store iframe element data for merging with main frame

**Flow**:
1. Extract tabId and frameId from sender
2. Extract iframeUrl, iframeOrigin, elements from message
3. Get or create tab's iframe cache
4. Store elements keyed by iframe URL with frameId, origin, timestamp
5. Check if we're waiting for iframes in pendingScanCache
6. Increment receivedIframeCount
7. If all iframes received: call sendIframeUpdate()

**Message format**:
```javascript
{
  type: 'iframe_intelligence',
  iframeUrl: string,
  iframeOrigin: string,
  elements: Array,
  timestamp: number
}
```

**Called by**: onMessage listener from iframe content scripts
**Calls**: sendIframeUpdate() when all iframes received

---

#### `handleDynamicIframeDetected(message, sender, sendResponse)`
**Purpose**: Track dynamically added iframes (CyberSource, Stripe, etc.)

**Flow**:
1. Extract tabId from sender
2. Get or create dynamicIframeTracking for tab
3. Add iframeSrc to tracking Set
4. Set timeout (5s) to send partial iframe update if intelligence not received
5. Timeout checks if still tracking, then calls sendIframeUpdate()

**Called by**: onMessage listener from main frame content script
**Calls**: setTimeout(), sendIframeUpdate()

---

#### `handleDynamicIframeLoaded(message, sender, sendResponse)`
**Purpose**: Remove iframe from tracking when loaded (should report intelligence soon)

**Flow**:
1. Extract tabId from sender
2. Remove iframeSrc from tracking Set
3. Log remaining iframe count

**Called by**: onMessage listener from main frame content script

---

#### `mergeIframeIntelligence(mainElements, tabId)`
**Purpose**: Merge iframe elements into main frame actionable elements with sequential IDs

**Parameters**:
- `mainElements` (Array): Main frame actionable elements
- `tabId` (number): Tab ID to get iframe cache for

**Returns**:
```javascript
{
  mergedElements: Array,        // Main + iframe elements
  iframeMappings: Map          // iframeUrl → { frameId, idMapping }
}
```

**Flow**:
1. Check if iframe cache exists for tab, return early if not
2. Clone mainElements to mergedElements
3. Start nextActionId after main frame elements (mainElements.length)
4. For each iframe in cache:
   - Skip focus helpers and hidden inputs
   - Assign final sequential ID (a_id_N)
   - Track mapping: localId → finalId
   - Convert to actionable element format with iframe metadata
   - Add to mergedElements
5. Store idMapping with frameId for each iframe
6. Return merged elements and mappings

**Element format**:
```javascript
{
  actionId: 'a_id_N',
  localId: string,
  tag: string,
  type: string,
  text: string,
  label: string,
  placeholder: string,
  name: string,
  domId: string,
  autocomplete: string,
  isIframeElement: true,
  iframeOrigin: string,
  iframeUrl: string,
  actionType: 'click' | 'select' | 'setValue'
}
```

**Called by**: handleIntelligenceUpdate(), sendIframeUpdate(), sendFinalIntelligence()

#### `updateInternalTabState(tabsInfo, forceRefresh)`
**Purpose**: Maintain enhanced internal state for all tabs with change detection

**Parameters**:
- `tabsInfo` (Array): Array of tab information objects
- `forceRefresh` (boolean): Clear all state before updating

**Flow**:
1. If forceRefresh: clear internalTabState and tabCache Maps
2. For each tab in tabsInfo:
   - Get old state from internalTabState
   - Check if changed (url, title, active, status different)
   - If changed:
     - Clear cache via clearTabCache()
     - Update internal state with enhanced tracking
     - Initialize domChanges, siteConfig, networkActivity objects
   - If new active tab: ensure content script fresh via ensureContentScriptFresh()
   - If URL changed: force content script refresh
3. Remove tabs that no longer exist (cleanup stale state)
4. Log summary stats

**State initialization**:
```javascript
internalTabState.set(tabId, {
  ...tabInfo,
  lastUpdate: Date.now(),
  needsFreshScan: true,
  contentScriptFresh: false,
  cacheCleared: true,
  domChanges: { totalChanges: 0, lastChangeTime: null, changeTypes: new Set(), lastMutationCount: 0 },
  siteConfigSent: false,
  lastConfigSent: null,
  currentDomain: null,
  currentFramework: 'generic',
  siteConfigError: null,
  lastConfigError: null
});
```

**Called by**: sendTabsInfo()
**Calls**: clearTabCache(), ensureContentScriptFresh()

#### `findActiveTab()`
**Purpose**: Find currently active accessible tab with multiple fallback strategies

**Returns**: Promise<Tab> or null

**Strategy sequence**:
1. **Strategy 1**: Find active tab in current window
   - Filter for accessible (not chrome://)
   - Get refreshed tab info via chrome.tabs.get()
2. **Strategy 2**: Find active tab in last focused window
3. **Strategy 3**: Find any accessible tab in current window
   - Sort by priority (non-chrome first, then active)
4. **Last Resort**: Find any visible accessible tab across all windows
   - Sort by active status

**Accessibility check**: Uses isTabAccessible() to filter

**Called by**: All command handlers needing active tab
**Calls**: chrome.tabs.query(), chrome.tabs.get(), chrome.windows.getCurrent(), isTabAccessible()

---

#### `isTabAccessible(tab)`
**Purpose**: Check if tab is accessible for content scripts

**Parameters**:
- `tab` (Object): Tab object

**Returns**: boolean

**Checks exclude**:
- No URL
- chrome://, chrome-extension://, about:, edge://, moz-extension://
- about:blank

**Called by**: findActiveTab()

### Command Handlers - DOM Operations

#### `handleDOMCommand(message)`
**Purpose**: Forward DOM commands to content script in active tab

**Handles commands**:
- waitFor, getText, click, getPageMarkdown, extractPageText
- scroll (page-by-page viewport scrolling)
- getCurrentTabInfo, getNavigationContext, searchActions
- discoverLoginControls, generateSiteMap, scanAndRegisterElements
- navigateBack, navigateForward, jumpToHistoryEntry
- getHistoryState, searchHistory, clearHistory

**Flow**:
1. Find active tab via findActiveTab()
2. Check if content script needs refresh (needsFreshScan or !contentScriptFresh)
3. If needed: call ensureContentScriptFresh()
4. Try to inject content script (may already exist)
5. **Call proactivelySendSiteConfig() - UNDEFINED FUNCTION**
6. Wait 100ms for content script initialization
7. Send message to content script via chrome.tabs.sendMessage
8. Handle response:
   - If error: send error response
   - If success: send success response
   - If scroll command: trigger post_scroll scan after 300ms
9. If generateSiteMap success: mark tab as successfully scanned

**Called by**: handleServerMessage()

## Known Issues and Notes

### 1. Undefined Variables/Functions

**actionInProgress**
- **Used in**: ensureContentScriptFresh(), handleDOMChanged(), handleNetworkActivity(), handleExecuteLLMAction(), handleExecuteActionWithHints()
- **Problem**: Variable is referenced but never declared
- **Impact**: Will cause ReferenceError if used before assignment in handleExecuteLLMAction()
- **Fix needed**: Declare at top of file with other state variables: `let actionInProgress = false;`

**proactivelySendSiteConfig(tabId, url)**
- **Called in**: ensureContentScriptFresh(), handleDOMCommand()
- **Problem**: Function is called but not defined anywhere in file
- **Impact**: Will cause ReferenceError when called
- **Fix needed**: Define function or remove calls

**getCurrentActiveTabId()**
- **Called in**: handleForceContentScriptReinjection()
- **Problem**: Function is called but not defined anywhere in file
- **Impact**: Will cause ReferenceError when called
- **Alternative**: Use findActiveTab() instead

### 2. Disabled Features

**DOM Mutation Rescans** (lines 2083-2105)
- Full rescans on DOM mutations disabled
- **Reason**: Caused counter accumulation, ID inconsistency, overlapping scans
- **Now**: content.js handles mutations incrementally via registerInteractiveSubtree

**Network Idle Rescans** (lines 2165-2178)
- Automatic rescans during action execution disabled
- **Reason**: Prevents invalidating action IDs before actions complete
- **Now**: Rescans triggered post-action instead

### 3. Deprecated Code

**triggerIntelligenceScan()** (lines 705-708)
- Marked as deprecated
- Redirects to requestScan()
- Kept for compatibility
- Should be removed after updating all callers

**tabScanState Map** (line 70)
- Marked as deprecated
- Still used in some listeners for cleanup
- Will be removed in future

---

### 4. Design Notes

**Scan Deduplication**
- Only one scan can run per tab at a time
- Same URL scans are skipped unless forced trigger
- Forced triggers: post_action, significant_dom_change, page_refresh, tab_switch, post_scroll, inputPattern_submit

**Action Coordination**
- actionInProgress flag prevents content script refresh during action execution
- Post-action scan triggered after 1s delay
- This ensures action IDs remain valid during execution

**Tab Accessibility**
- chrome://, about:, chrome-extension:// URLs are not accessible for content scripts
- findActiveTab() implements multiple fallback strategies
- Prioritizes non-chrome tabs over chrome:// tabs

**Keep-Alive Strategy**
- Multiple redundant mechanisms to prevent suspension
- Port connections from content scripts most reliable
- Offscreen document fallback for when no tabs available
- Periodic checks and alarms as additional safety nets

**Progressive Output**
- Main frame intelligence sent immediately to LLM
- Iframe elements sent separately when ready
- Prevents blocking LLM on slow cross-origin iframes
- 5s timeout ensures partial results sent if iframes timeout

**Orb State Session Logic**
- First page of browser session uses defaults (position: null, chatVisible: true)
- Subsequent pages use saved orbState
- Flag orbDefaultApplied tracks this (0 = not applied, 1 = applied)

## Summary

The service worker is the central nervous system of Om_E_Web, orchestrating:
- **Bidirectional communication** between server and content scripts
- **Tab lifecycle management** with intelligent state tracking and change detection
- **Scan coordination** with deduplication and progressive iframe output
- **Keep-alive mechanisms** to prevent Chrome suspension using multiple redundant strategies
- **Site configuration distribution** for per-domain behavior
- **Smart capability routing** between browser-level and page-level operations
- **Orb state persistence** across page navigations with session-aware defaults
- **HUD interface control** for overlay visibility and theme management
- **Iframe intelligence merging** with sequential ID assignment and DOM synchronization

It implements a robust, event-driven architecture with multiple fallback strategies for reliability. Key to its operation is the clear separation between:
- **Browser-level operations** (handled directly via Chrome APIs)
- **Page-level operations** (forwarded to content scripts)
- **State synchronization** (maintaining consistency across components)
- **UI state persistence** (orb position, theme, chat visibility, panel size, active chat)
- **Progressive output** (main frame sent immediately, iframes sent separately)
